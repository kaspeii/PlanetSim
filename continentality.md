Смысл в этом есть, и довольно конкретный. Сейчас ваша «континентальность» — это по сути **«насколько далеко от океана»**, и она измеряет только сушу. Океан у вас весь одинаковый (`distance_to_ocean = 0`), независимо от того, это открытый Тихий океан или Балтийское море, окружённое сушей. А это физически разные вещи.

### 🌊 Почему это имеет физический смысл: маргинальные моря

Ключевой пример — **внутренние и окраинные моря**. Балтика, Средиземное, Чёрное, Гудзонов залив — это вода, но по термическому поведению они ближе к суше:

- **Малая теплоёмкость:** мало воды → быстро нагревается и остывает → большая сезонная амплитуда.
- **Быстрое замерзание:** Балтика и Гудзонов залив замерзают, хотя открытый океан на той же широте — нет.
- **Более континентальный климат на берегах:** побережья маргинальных морей имеют более суровые зимы, чем побережья открытого океана.

Ваш текущий код этого не различает: и Балтика, и открытая Атлантика получают `moderation = base_ocean_moderation`, а `surface_mult = 0.35`. В реальности Балтика должна вести себя «континентальнее» — с большей амплитудой, более выраженным зимним максимумом, более ранним ледоставом.

### 🔄 Что конкретно изменится в симуляции

1. **Температура:** маргинальные моря получат больше сезонного размаха, открытый океан — меньше. Сейчас у вас все океаны одинаково «стабильны».
2. **Давление:** `surface_mult` перестанет быть бинарным (0.35 для океана, 1.0 для суши). Вместо этого — плавная функция от континентальности. Это уберёт искусственный «ступенчатый» переход давления на береговой линии и даст слабые барические центры над маргинальными морями.
3. **Лёд:** ваш батиметрический хак (`smoothstep(-0.06, -0.22, elev)`) уже частично ловит мелководье. Континентальность дополнит его: мелкое море **у берега** замёрзнет легче, чем мелкое море **в открытом океане** (редкий случай, но возможный — атоллы, банки).
4. **Ветер:** термический градиент станет более гладким на побережьях, уберутся артефакты «излома» ветра на береговой линии.

### 🧮 Как это реализовать: знаковая континентальность

Замените `compute_ocean_distance` на `compute_continentality`, которая делает **два BFS**:

```rust
pub fn compute_continentality(
    topology: &WorldTopology,
    geology: &GeologyLayer,
    climate: &mut ClimateLayer,
    config: &ClimateConfig,
) {
    let num_cells = topology.cells.len();
    // ... (существующая логика определения is_ocean через BFS по связности) ...

    // BFS 1: расстояние до океана (для суши)
    let mut dist_to_ocean = vec![u32::MAX; num_cells];
    let mut queue = VecDeque::new();
    for i in 0..num_cells {
        if is_ocean[i] {
            dist_to_ocean[i] = 0;
            queue.push_back(i);
        }
    }
    // ... стандартный BFS ...

    // BFS 2: расстояние до суши (для океана)
    let mut dist_to_land = vec![u32::MAX; num_cells];
    queue.clear();
    for i in 0..num_cells {
        if !is_ocean[i] {
            dist_to_land[i] = 0;
            queue.push_back(i);
        }
    }
    // ... стандартный BFS ...

    // Знаковая континентальность: -1 = открытый океан, 0 = берег, +1 = глубь континента
    for i in 0..num_cells {
        climate.continentality[i] = if is_ocean[i] {
            let norm = (dist_to_land[i] as f32 / config.ocean_continentality_scale).min(1.0);
            -smoothstep01(norm)  // -1 далеко от суши, 0 у берега
        } else {
            let norm = (dist_to_ocean[i] as f32 / config.land_continentality_scale).min(1.0);
            smoothstep01(norm)   // 0 у берега, +1 в глуби континента
        };
    }
}
```

Новые константы в `ClimateConfig`:

```rust
pub ocean_continentality_scale: f32,  // расстояние в клетках, где океан считается «полностью открытым». Рекомендую 10–15
pub land_continentality_scale: f32,   // расстояние, где суша считается «полностью континентальной». Рекомендую 15–25
```

### 🔧 Как это использовать в существующем коде

**1. `calc_radiative_sea_temp` — замена `moderation_factor`:**

```rust
// Было:
// let moderation_factor = 1.0 / (1.0 + real_dist * config.continentality_factor * 20.0);
// let moderation = config.base_ocean_moderation * moderation_factor;

// Стало:
let c = climate.continentality[i]; // -1..+1
// Океан (c < 0): moderation выше базовой (открытый океан стабильнее)
// Суша (c > 0): moderation падает до 0
let moderation = if c < 0.0 {
    config.base_ocean_moderation * (1.0 + c.abs() * 0.5)
} else {
    config.base_ocean_moderation * (1.0 - c)
};
```

**2. `compute_season_pressure_and_winds` — замена `surface_mult`:**

```rust
// Было:
// let surface_mult = if distance_to_ocean[i] == 0 { 0.35 } else { 1.0 };

// Стало:
let c = climate.continentality[i];
let surface_mult = 0.35 + 0.65 * smoothstep01((c + 0.3) / 1.3);
// c = -1  → 0.35 (открытый океан)
// c =  0  → 0.65 (берег)
// c = +1  → 1.0  (глубь континента)
```

Это убирает разрыв на побережье и даёт маргинальным морям промежуточный вес.

**3. Батиметрия — можно оставить как есть** или слегка модифицировать: добавить `+ c.abs() * 0.5` к `bathymetry_shift` для океана, чтобы мелкое море у берега замерзало ещё легче.

### ⚠️ Стоит ли это делать

**За:**
- Физически осмысленно (маргинальные моря — реальный эффект).
- Убирает бинарность океан/суша в давлении и температуре → более гладкие поля.
- Даёт визуально заметную разницу: Балтика ведёт себя иначе, чем Атлантика.
- Дёшево: второй BFS — это O(N), считается один раз.

**Против:**
- Добавляет одну новую переменную в `ClimateLayer` и две константы в конфиг.
- Формулы `moderation` и `surface_mult` придётся перекалибровать (старые значения `continentality_factor` и `0.35` больше не будут работать как раньше).
- Эффект заметен главным образом на маргинальных морях и побережьях — если у вас на карте в основном открытые океаны и крупные континенты, выигрыш будет скромным.

**Мой вердикт:** делать стоит, если у вас на картах есть внутренние моря, заливы и сложные побережья — там это даст заметный визуальный и физический эффект. Если океаны в основном открытые, а континенты массивные — можно отложить, выигрыш будет небольшим. В любом случае это дешевле и полезнее, чем вертикальные уровни атмосферы на текущем этапе.
